# LLM_FORWARD_VALIDITY: hvorfor historiske LLM-handelstest kan kende fremtiden (direktørordre 58 P2, U5)

**Status:** DESIGN-ONLY. Ingen model aktiveret, ingen nøgle, ingen agent, ingen API-udgift, ingen markedsdata.
**Skrevet:** 2026-11-09 ca. 00:40 lokal (2026-11-08 ca. 23:40 UTC), tid tjekket med `date`.
**Metode:** arXiv-sider, OpenAI's modeldokumentation, et GitHub-issue og én praktikerblog, læst med WebFetch.
Ingen kurser er hentet for at efterprøve tal.
**Mærker:** VERIFIED = selve kilden er læst. ABSTRACT = kun abstract/metadata. UNVERIFIED = ikke bekræftet.

**Konklusion:** En historisk backtest af en hostet LLM er ikke bevis. Modellen kan have set udfaldet. Den eneste gyldige
vej er en fremadtest efter en frosset models dokumenterede vidensgrænse. Den er ikke tilladt for lab'et nu.

## 1. Sådan lækker fremtiden ind

| Kanal | Hvad sker der | Eksempel |
|---|---|---|
| Vidensgrænse (pretraining) | Testperioden ligger før eller i modellens træningsdata. Modellen "forudsiger" noget, den har læst | En 2023-model testet på 2022 |
| Memorering af kurser og nyheder | Modellen husker afkast for et firma og en dato | Gao, Jiang & Yan: nøjagtigheden er højest, hvor modellen kan genkalde udfaldet |
| Uklar grænse | Den officielle grænse er ikke den faktiske. Nye snapshots og eftertræning kan tilføje nyere data | Kommentar i TradingAgents issue #203 |
| Nyheders tidsstempler | Hentningen giver dagens version, ikke den der fandtes dengang. Artikler opdateres, overskrifter ændres | TradingAgents' hentere gav "real time information" (#203) |
| Reviderede data | Makrotal og regnskaber revideres. En database viser den endelige værdi, ikke den første | BNP, beskæftigelse |
| Overlevelse i tickervalg | Man vælger kendte vindere eller firmaer, der findes i dag | AAPL, NVDA, MSFT, META, GOOGL valgt i 2024 |
| Distraktion | Modellen bruger sin viden om firmaet i stedet for teksten | Glasserman & Lin: anonymiserede overskrifter klarede sig bedre in-sample |
| Modeldrift | En hostet model ændres eller lukkes. Testen kan ikke gentages | o1-preview er lukket |

## 4. Hvorfor publicerede Sharpe-tal ikke generaliserer

- **Kort vindue:** ca. 60 handelsdage (v7) eller ca. 105 (v1). Med iid-antagelse er standardfejlen på en årlig Sharpe
  på 8,21 ca. 2,2 ved 60 dage og ca. 1,7 ved 105 dage (Lo-formlen; beregning, ikke data). Seriekorrelation gør den større.
- **Få tickere:** tre store US-aktier i ét regime. FINSABER finder, at fordelen skrumper over 20 år og > 100 aktier.
- **Ingen omkostninger:** daglige signaler uden gebyr og spread.
- **Udvælgelse:** fem tickere nævnt, tre vist. Ukendt antal prompts, roller og versioner prøvet. Lab'ets held-tjek
  (U3, forventet maks-Sharpe for N forsøg) kan ikke bruges, fordi N ikke er oplyst.
- **Look-ahead:** se afsnit 1 og issue #203.

## 5. Krav til en gyldig LLM-test i lab'et

| Krav | Hvorfor | Lab'et nu |
|---|---|---|
| Point-in-time model: frosset version (snapshot eller vægte), dokumenteret grænse, test strengt efter | Ellers kan modellen kende udfaldet | Ingen model aktiveret |
| Historisk test kun med en kronologisk konsistent model (ChronoGPT, DatedGPT), hvis grænse ligger før vinduet | Eneste måde at bruge fortiden ærligt | Ikke tilladt (modelaktivering); 2024 er holdout, 2025 → reserveret |
| Frosne prompts, roller og værktøjer, committet med sha256 før første kald | Ellers er prompten en fri parameter | – |
| Temperatur 0 og fast seed, hvor muligt; ellers gentagne kald og fordeling | Svar varierer mellem kald | – |
| Log af hvert kald: model-id, prompt-hash, input, output, tid, pris | Efterprøvning | – |
| Tidsstemplede input: kun data med `available_ts` ≤ beslutningstid; gem rå input | Nyheder og data ændres bagefter | Lab'ets point-in-time-regel findes |
| Omkostninger: API-$ er rigtige penge; handelsgebyr og spread som lab'ets model | Netto, ikke brutto | **API-$ er forbudt** |
| Reproducerbarhed: hostede modeller ændres og lukkes | Testen skal kunne gentages | Kræver egne vægte eller dated snapshot |
| Multipel test: hver prompt- og rollevariant tæller som et forsøg (factory-registret, Holm/BH, DSR) | Ellers vinder heldet | Findes i lab'et |
| Benchmark beregnet af lab'et selv, med samme vindue og omkostninger | Undgå fortegnsfejl som i afsnit 3 | Findes |

## 6. Lab'ets rammer

- Ingen API-nøgler. Ingen modelaktivering. Ingen agentaktivering. Ingen nye værter.
- API-udgifter er rigtige penge og er forbudt for lab'et nu.
- En lokal model med åbne vægte undgår API-$, men er stadig en modelaktivering og kræver en ny beslutning.
- Ingen formel hypotese oprettes (ordre 58 P3).

## 7. Konklusion

- Historiske LLM-handelstest, også TradingAgents, er ikke evidens for lab'et: kort vindue, få tickere, ingen
  omkostninger, uklart vindue og dokumenteret datalæk.
- Den eneste gyldige vej er en fremadtest: frosset model, frosne prompts, alle kald logget, start efter låsen.
- Den vej kræver nøgle eller modelaktivering og løbende udgift. **Den er ikke autoriseret nu. NO-GO.**
